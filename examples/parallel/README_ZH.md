# llama.cpp/example/parallel

模拟并行处理传入请求的简化示例。

## 简介

本示例模拟服务器环境中如何并行处理多个客户端请求，展示了如何高效管理和调度并发推理任务。

## 快速开始

生成 128 个客户端请求（`-ns 128`），模拟 8 个并发客户端（`-np 8`）。系统提示词是共享的（`-pps`），意味着它在开始时只计算一次。客户端请求由最多 10 个垃圾问题（`--junk 10`）后跟实际问题组成。

```bash
llama-parallel -m model.gguf -np 8 -ns 128 --top-k 1 -pps --junk 10 -c 16384
```

## 参数说明

| 参数 | 说明 |
|------|------|
| `-m, --model` | 模型文件路径（必需） |
| `-np, --n-parallel` | 并行处理的客户端数量 |
| `-ns, --n-seqs` | 生成的总序列数量 |
| `--top-k 1` | Top-K 采样参数（贪婪采样） |
| `-pps, --prompt-shared` | 共享系统提示词 |
| `--junk` | 每个请求前的垃圾问题数量 |
| `-c, --ctx-size` | 上下文窗口大小 |
| `-ngl, --n-gpu-layers` | GPU 层数 |
| `-t, --threads` | 使用的线程数 |

## 工作流程

1. **初始化阶段**：
   - 加载模型
   - 设置共享系统提示词
   - 初始化并行处理队列

2. **请求生成**：
   - 生成指定数量的请求序列
   - 每个请求包含垃圾问题和实际问题

3. **并行处理**：
   - 同时处理多个客户端请求
   - 管理上下文和 KV 缓存

4. **结果收集**：
   - 收集所有请求的响应
   - 统计性能指标

## 功能特点

- **共享提示词**：系统提示词只计算一次，提高效率
- **并行调度**：同时处理多个请求
- **资源管理**：高效管理 GPU 内存和计算资源
- **垃圾过滤**：通过垃圾问题测试系统稳定性

## 使用场景

- **服务器测试**：模拟真实服务器负载
- **性能评估**：评估并行推理性能
- **压力测试**：测试系统在高并发下的表现
- **资源优化**：优化内存和计算资源分配

## 性能指标

示例会输出以下性能指标：
- 每个请求的处理时间
- 平均延迟
- 吞吐量（requests/second）
- GPU 利用率
- 内存使用情况

## 模型建议

> [!NOTE]
> 建议使用基础模型（base models）进行此示例。指令微调模型可能无法正确遵循这里指定的自定义聊天模板，因此结果可能不如预期。

推荐的模型类型：
- LLaMA 基础模型
- Qwen 基础模型
- Pythia 基础模型

## 配置建议

| 场景 | 并行数 | 序列数 | 上下文大小 | 垃圾问题数 |
|------|--------|--------|------------|------------|
| 轻量测试 | 4 | 32 | 4096 | 5 |
| 标准测试 | 8 | 128 | 8192 | 10 |
| 重负载测试 | 16 | 512 | 16384 | 20 |
| 极限测试 | 32 | 1024 | 32768 | 50 |

## 性能优化

- **GPU 利用**：尽可能使用 GPU 层（`-ngl 99`）
- **内存管理**：合理设置上下文大小
- **批处理**：利用批处理提高吞吐量
- **线程数**：设置为 CPU 核心数或略高

## 注意事项

- 需要足够的 GPU 内存支持多个并发请求
- 过多的并行可能导致内存不足
- 垃圾问题用于测试，实际应用中不需要
- 确保使用基础模型而非指令模型

## 调试技巧

- 使用较小的序列数进行初始测试
- 逐步增加并行数和序列数
- 监控 GPU 内存使用情况
- 查看性能指标以识别瓶颈
