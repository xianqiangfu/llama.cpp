# llama.cpp/example/batched-bench

用于基准测试 `llama.cpp` 批处理解码性能

## 用法

有两种操作模式：

- `prompt not shared` - 每个批处理都有一个单独的大小为 `PP` 的提示词（即 `N_KV = B*(PP + TG)`）
- `prompt is shared` - 所有批处理使用一个大小为 `PP` 的公共提示词（即 `N_KV = PP + B*TG`）

```bash
./llama-batched-bench -m model.gguf -c 2048 -b 2048 -ub 512 -npp 128,256,512 -ntg 128,256 -npl 1,2,4,8,16,32 [-pps]

# LLaMA 7B, F16, N_KV_MAX = 16384 (8GB), 提示词不共享
./llama-batched-bench -m ./models/llama-7b/ggml-model-f16.gguf -c 16384 -b 2048 -ub 512 -ngl 99

# LLaMA 7B, Q8_0, N_KV_MAX = 16384 (8GB), 提示词共享
./llama-batched-bench -m ./models/llama-7b/ggml-model-q8_0.gguf -c 16384 -b 2048 -ub 512 -ngl 99 -pps

# 自定义批处理集合
./llama-batched-bench -m ./models/llama-7b/ggml-model-q8_0.gguf -c 2048 -b 512 -ub 512 -ngl 999 -npp 128,256,512 -ntg 128,256 -npl 1,2,4,8,16,32
```

## 参数说明

| 参数 | 说明 |
|------|------|
| `-m model.gguf` | 指定要测试的 GGUF 模型文件 |
| `-c N` | 上下文大小（最大 KV 缓存） |
| `-b N` | 逻辑最大批处理大小 |
| `-ub N` | 物理最大批处理大小 |
| `-ngl N` | 卸载到 GPU 的层数 |
| `-npp PP,PP,...` | 要测试的提示词令牌数列表（逗号分隔） |
| `-ntg TG,TG,...` | 要测试的生成令牌数列表（逗号分隔） |
| `-npl PL,PL,...` | 要测试的批处理数列表（逗号分隔） |
| `-pps` | 启用提示词共享模式 |
| `--output-format` | 输出格式：`markdown`（默认）或 `jsonl` |

## 示例结果

- `PP` - 每批处理的提示词令牌数

## 使用场景

此工具对于评估和优化 llama.cpp 在批处理场景下的性能非常有用，特别是在：

1. **多用户并发**：测试多个用户同时查询模型时的性能
2. **批处理推理**：评估不同批处理大小对吞吐量的影响
3. **GPU 利用率**：优化 GPU 内存和计算资源的使用
4. **模型对比**：比较不同量化或模型变体的性能

## 性能调优建议

1. **批处理大小**：增加批处理大小通常能提高吞吐量，但会减少延迟
2. **提示词共享**：对于相同的提示词，启用 `-pps` 可以显著减少提示词处理时间
3. **GPU 层数**：使用 `-ngl` 参数将更多层卸载到 GPU 可以提高性能
4. **批处理大小配置**：调整 `-b`（逻辑批处理）和 `-ub`（物理批处理）可以优化内存使用和性能
