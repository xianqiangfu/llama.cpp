# 模型选择与量化最佳实践

## 概述

选择合适的模型和量化策略是 llama.cpp 成功部署的关键。本文档提供了模型选择、量化策略和最佳实践的详细指南，帮助用户在不同的应用场景和硬件环境下做出最优决策。

## 模型选择指南

### 按应用场景选择

#### 1. 对话和聊天应用

**推荐模型：**
- Llama-3-8B-Instruct / 70B-Instruct
- Mistral-7B-Instruct-v0.3
- Qwen-14B-Chat / 72B-Chat
- ChatGLM3-6B / GLM-4-9B

**选择标准：**
- 良好的指令遵循能力
- 适当的上下文长度
- 多轮对话能力
- 推理速度要求

**推荐配置：**
```bash

llama-cli -m llama-3-8b-instruct-q4_k_m.gguf -c 8192 -ngl 35

# 高质量需求
llama-cli -m llama-3-70b-instruct-q5_k_m.gguf -c 16384 -ngl all
```

- 代码理解能力强

### 按硬件资源选择

#### 1. 高端 GPU（24GB+ VRAM）

**推荐模型：**
- Llama-3-70B-Instruct (Q4/Q5)
- Qwen-72B-Chat (Q4/Q5)
- 任意 70B 参数模型

**量化策略：**
- Q4_K_M 或 Q5_K_M 平衡选择
- Q6_K 或 Q8_0 追求最高质量
- 考虑重要性矩阵优化

#### 2. 中端 GPU（12-16GB VRAM）

**推荐模型：**
- Llama-3-8B / 34B (Q4/Q5)
- Mistral-7B (Q4/Q5)
- Qwen-14B / 32B (Q4/Q5)

**量化策略：**
- Q4_K_M 为主要选择
- Q5_K_S 用于质量关键应用
- Q3_K_M 用于资源受限场景

#### 3. 低端 GPU（8GB 或更少 VRAM）

**推荐模型：**
- Llama-3-8B (Q3/Q4)
- Mistral-7B (Q3/Q4)
- Qwen-7B (Q3/Q4)
- 小型模型（3B-4B）

**量化策略：**
- Q3_K_M 或 Q4_K_S
- 考虑 CPU offload
- 使用更小的模型

#### 4. CPU 专用环境

**推荐模型：**
- Qwen-7B / 14B
- Llama-3-8B
- Mistral-7B
- 针对优化的模型

**量化策略：**
- Q4_K_M 平衡选择
- Q3_K_M 加快推理速度
- 考虑 BLIS 优化

| Q5_K_S | ~5 | 33% | +50-80% | 低 | 平衡选择 |

### 量化选择决策树

```
开始
  │
  ├─ 是否需要最高质量？
  │   ├─ 是 → F16/BF16 或 Q8_0
  │   └─ 否 → 继续
  │
  ├─ 硬件资源如何？
  │   ├─ 充足 (16GB+ VRAM) → Q5_K_M / Q6_K
  │   ├─ 适中 (8-16GB VRAM) → Q4_K_M / Q5_K_S
  │   ├─ 有限 (4-8GB VRAM) → Q3_K_M / Q4_K_S
  │   └─ 严重受限 (<4GB VRAM) → Q2_K / IQ2_XS
  │
  ├─ 是否对精度非常敏感？
  │   ├─ 是 → 选择更高的精度 (Q5+)
  │   └─ 否 → 继续当前选择
  │
  ├─ 后端支持如何？
  │   ├─ 完整支持 → IQ 系列可选
  │   ├─ 部分支持 → 选择 K 系列
  │   └─ 基础支持 → 使用 Q4_0/Q8_0
  │
  └─ 最终确认量化类型
```

### 量化实践指南

#### 1. 基本量化流程

```bash
# 1. 准备原始模型 (FP16/F32)
# 确保 model-f16.gguf 已准备好

# 2. 生成重要性矩阵 (推荐)
./llama-imatrix -m model-f16.gguf \
  -f calibration.txt \
  -o imatrix.dat \
  --chunks 500

# 3. 执行量化
./llama-quantize \
  --imatrix imatrix.dat \
  model-f16.gguf \
  model-q4_k_m.gguf \
  Q4_K_M

# 4. 验证质量
./llama-perplexity -m model-q4_k_m.gguf -f test.txt
./test-quantize-stats -m model-f16.gguf -p -v
```

#### 2. 保护关键张量

```bash
# 保护输出层
./llama-quantize \
  --leave-output-tensor \
  model-f16.gguf \
  model-q4_k_m.gguf \
  Q4_K_M

# 指定特定张量的量化类型
./llama-quantize \
  --tensor-type attn_q=q8_0 \
  --tensor-type output.weight=f16 \
  model-f16.gguf \
  model-q4_k_m.gguf \
  Q4_K_M
```

#### 3. 批量量化不同级别

```bash
#!/bin/bash
# 批量量化脚本

MODEL="model-f16.gguf"
IMATRIX="imatrix.dat"

# 量化到不同级别
for QTYPE in Q2_K Q3_K_M Q4_K_M Q5_K_M Q6_K Q8_0; do
    OUTPUT="model-${QTYPE,,}.gguf"
    echo "Quantizing to $QTYPE..."
    ./llama-quantize --imatrix $IMATRIX $MODEL $OUTPUT $QTYPE
done

# 比较质量
for MODEL in model-*.gguf; do
    echo "Testing $MODEL..."
    ./llama-perplexity -m $MODEL -f test.txt
done
```

- GPU 层：尽可能多

  -c 4096 \
  --parallel 4 \
  -ngl 35 \
  --ctx-size 4096

./llama-cli -m model-q4_k_m.gguf \

## 常见问题解决

### 1. 质量不符合预期

**问题：** 量化后质量下降明显

**解决方案：**
- 提高量化级别 (Q4 → Q5)
- 使用重要性矩阵
- 保护关键张量
- 重新校准量化参数

### 2. 性能不佳

**问题：** 推理速度慢

**解决方案：**
- 使用更激进的量化
- 增加 GPU 层数
- 优化批处理大小
- 检查后端支持

### 3. 内存不足

**问题：** OOM 错误

**解决方案：**
- 降低量化级别
- 减少上下文大小
- 减少 GPU 层数
- 启用 mmap

### 4. 兼容性问题

**问题：** 模型无法运行

**解决方案：**
- 检查后端支持
- 验证模型格式
- 更新驱动和软件
- 尝试不同的量化类型
