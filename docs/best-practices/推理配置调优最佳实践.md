# 推理配置调优最佳实践

## 概述

推理配置调优是优化 llama.cpp 性能和质量的关键步骤。合理的配置可以显著提升推理速度、降低资源消耗，并在必要时提高输出质量。本文档提供了推理配置的详细调优指南，包括参数说明、优化策略和最佳实践。

## 核心推理参数

### 基础参数

#### 1. 模型和路径参数

| 参数 | 简写 | 默认值 | 说明 | 调优建议 |
|------|------|--------|------|----------|
| `-m, --model` | - | - | 模型文件路径 | 必须参数，选择合适的模型 |
| `--model-path` | - | - | 模型搜索路径 | 用于模型目录组织 |
| `--lora` | - | - | LoRA 适配器路径 | 用于微调模型 |
| `--lora-base` | - | - | LoRA 基础模型 | 用于适配器兼容性 |

#### 2. 上下文和生成参数

| 参数 | 简写 | 默认值 | 说明 | 调优建议 |
|------|------|--------|------|----------|
| `-c, --ctx-size` | - | 512 | 上下文窗口大小 | 根据需求调整，增加会增加内存使用 |
| `-n, --n-predict` | - | -1 | 最大生成 token 数 | -1 表示无限，有限值提高可控性 |
| `--n-keep` | - | 0 | 保留的提示词 token 数 | 用于多轮对话保持上下文 |
| `--n-trainable` | - | 0 | 可训练层数量 | 用于微调场景 |
| `--n-emax` | - | 0 | 最大嵌入维度 | 用于内存优化 |

#### 3. 推理控制参数

| 参数 | 简写 | 默认值 | 说明 | 调优建议 |
|------|------|--------|------|----------|
| `-b, --batch-size` | - | 512 | 批处理大小 | 大小影响性能，需测试优化 |
| `-ub, --ubatch-size` | - | 512 | 微批处理大小 | 用于 GPU 内存管理 |
| `--n-cpu` | - | 8 | CPU 线程数 | 根据 CPU 核心数调整 |
| `-t, --threads` | - | 8 | 推理线程数 | 考虑 CPU 核心和内存带宽 |

### 采样参数

#### 温度和多样性控制

| 参数 | 简写 | 默认值 | 说明 | 调优建议 |
|------|------|--------|------|----------|
| `--temp` | - | 0.8 | 采样温度 | 0.7-1.0 范围，低温度更确定 |
| `--top-p` | - | 0.9 | Nucleus 采样阈值 | 0.8-0.95 范围，控制多样性 |
| `--top-k` | - | 40 | Top-k 采样数量 | 20-100 范围，限制候选词 |
| `--min-p` | - | 0.05 | 最小概率阈值 | 0.01-0.1 范围，控制多样性 |

#### 重复和惩罚控制

| 参数 | 简写 | 默认值 | 说明 | 调优建议 |
|------|------|--------|------|----------|
| `--repeat-penalty` | - | 1.0 | 重复惩罚系数 | 1.0-1.5 范围，避免重复 |
| `--repeat-last-n` | - | 64 | 重复惩罚窗口 | 32-256 范围，控制惩罚范围 |
| `--frequency-penalty` | - | 0.0 | 频率惩罚 | 0.0-1.0 范围，惩罚常见词 |
| `--presence-penalty` | - | 0.0 | 存在惩罚 | 0.0-1.0 范围，鼓励多样性 |

#### 高级采样参数

| 参数 | 简写 | 默认值 | 说明 | 调优建议 |
|------|------|--------|------|----------|
| `--tfs` | - | 1.0 | Tail Free Sampling | 0.9-1.0 范围，提高连贯性 |
| `--typical` | - | 1.0 | Typical Sampling | 0.9-1.0 范围，提高典型性 |
| `--mirostat` | - | 0 | Mirostat 模式 | 0/1/2，控制困惑度 |
| `--mirostat-lr` | - | 0.1 | Mirostat 学习率 | 0.05-0.2 范围 |
| `--mirostat-ent` | - | 5.0 | Mirostat 目标困惑度 | 2-10 范围 |

## 性能调优策略

### 1. 吞吐量优化

**目标：** 最大化每秒处理的 token 数

**调优步骤：**

```bash
# 基准测试
./llama-cli -m model.gguf -p "test" -n 1000 --time-detail

# 优化批处理大小
for BS in 128 256 512 1024; do
    ./llama-cli -m model.gguf -b $BS -p "test" -n 1000 --time-detail
done

# 优化 GPU 层数
for NGL in 20 25 30 35 40; do
    ./llama-cli -m model.gguf -ngl $NGL -p "test" -n 1000 --time-detail
done

# 优化线程数
for T in 4 8 12 16; do
    ./llama-cli -m model.gguf -t $T -p "test" -n 1000 --time-detail
done
```

**最佳配置：**
- 批处理大小：512-1024（根据内存）
- GPU 层数：尽可能多
- 线程数：CPU 核心数或略少
- 微批大小：与批处理大小相同或更大

### 2. 延迟优化

**目标：** 最小化首 token 延迟和生成延迟

**调优步骤：**

```bash
# 测试延迟
./llama-cli -m model.gguf -p "test" -n 100 --time-detail

# 减少批处理
./llama-cli -m model.gguf -b 1 -p "test" -n 100 --time-detail

# 优化 GPU 层数
./llama-cli -m model.gguf -ngl all -p "test" -n 100 --time-detail

# 启用 Flash Attention
./llama-cli -m model.gguf -fa on -p "test" -n 100 --time-detail
```

**最佳配置：**
- 批处理大小：1-8（低延迟）
- GPU 层数：尽可能多
- 微批大小：与批处理大小相同
- Flash Attention：启用

### 3. 内存优化

**目标：** 在有限内存下运行最大可能的模型

**调优步骤：**

```bash
# 检查内存使用
./llama-cli -m model.gguf -p "test" -n 100 --verbose

# 减少上下文大小
for CTX in 2048 4096 8192; do
    ./llama-cli -m model.gguf -c $CTX -p "test" -n 100
done

# 优化 KV 缓存
./llama-cli -m model.gguf --cache-type-k q8_0 --cache-type-v q8_0 -p "test" -n 100

# 减少 GPU 层数
for NGL in 10 20 30; do
    ./llama-cli -m model.gguf -ngl $NGL -p "test" -n 100
done

# 启用 mmap
./llama-cli -m model.gguf --mmap -p "test" -n 100
```

**最佳配置：**
- 上下文大小：根据需求最小化
- KV 缓存：使用量化类型
- GPU 层数：根据内存平衡
- 内存映射：启用

### 4. 质量优化

**目标：** 提高输出质量和多样性

**调优步骤：**

```bash
# 测试不同采样参数
for TEMP in 0.7 0.8 0.9 1.0; do
    ./llama-cli -m model.gguf --temp $TEMP -p "test" -n 200
done

# 测试不同采样策略
./llama-cli -m model.gguf --top-p 0.9 -p "test" -n 200
./llama-cli -m model.gguf --top-k 40 -p "test" -n 200
./llama-cli -m model.gguf --min-p 0.05 -p "test" -n 200

# 测试重复惩罚
for RP in 1.0 1.1 1.2 1.3; do
    ./llama-cli -m model.gguf --repeat-penalty $RP -p "test" -n 200
done

# 测试高级采样
./llama-cli -m model.gguf --mirostat 2 --mirostat-ent 5.0 -p "test" -n 200
```

**最佳配置：**
- 温度：0.7-1.0（根据需求）
- Top-p：0.9-0.95
- Top-k：20-50
- 重复惩罚：1.1-1.3
- 高级采样：根据需求选择

## 常见问题解决

### 1. 性能低于预期

**可能原因：**
- GPU 层数不足
- 批处理大小不当
- 线程数设置不当
- 驱动或后端问题

**解决方案：**
```bash
# 检查 GPU 使用
./llama-cli -m model.gguf -ngl all -p "test" -n 100 --verbose

# 优化批处理
./llama-cli -m model.gguf -b 512 -p "test" -n 1000 --time-detail

# 调整线程数
./llama-cli -m model.gguf -t 8 -p "test" -n 1000 --time-detail
```

### 2. 内存不足

**可能原因：**
- 上下文大小过大
- 模型太大
- KV 缓存占用过多
- 批处理大小过大

**解决方案：**
```bash
# 减少上下文
./llama-cli -m model.gguf -c 2048 -p "test" -n 100

# 量化 KV 缓存
./llama-cli -m model.gguf \
  --cache-type-k q8_0 \
  --cache-type-v q8_0 \
  -p "test" -n 100

# 减少 GPU 层数
./llama-cli -m model.gguf -ngl 20 -p "test" -n 100
```

### 3. 输出质量不佳

**可能原因：**
- 采样参数不当
- 温度设置错误
- 重复惩罚不足
- 模型本身质量问题

**解决方案：**
```bash
# 调整温度
./llama-cli -m model.gguf --temp 0.8 -p "test" -n 200

# 优化采样策略
./llama-cli -m model.gguf --top-p 0.9 --top-k 40 -p "test" -n 200

# 增加重复惩罚
./llama-cli -m model.gguf --repeat-penalty 1.2 -p "test" -n 200
```

### 4. 稳定性问题

**可能原因：**
- 驱动版本不兼容
- 内存泄漏
- 过热问题
- 硬件问题

**解决方案：**
```bash
# 更新驱动
sudo apt update
sudo apt upgrade nvidia-driver

# 监控温度
watch -n 1 nvidia-smi

# 检查内存泄漏
valgrind --leak-check=full ./llama-cli -m model.gguf -p "test" -n 100
```

## 自动化调优脚本

### 性能基准测试

```bash
#!/bin/bash
# benchmark.sh - 自动性能基准测试

MODEL=${1:-"model.gguf"}
RESULTS_DIR="benchmark_results"
mkdir -p $RESULTS_DIR

# 测试不同配置
for BS in 128 256 512 1024; do
    for NGL in 20 30 35 40; do
        echo "Testing BS=$BS, NGL=$NGL"
        ./llama-cli -m $MODEL \
            -b $BS \
            -ngl $NGL \
            -p "The quick brown fox jumps over the lazy dog." \
            -n 1000 \
            --time-detail > \
            "$RESULTS_DIR/bs_${BS}_ngl_${NGL}.txt"
    done
done

# 生成报告
echo "Generating report..."
python3 << EOF
import os
import re

results_dir = "$RESULTS_DIR"
summary = []

for file in os.listdir(results_dir):
    if file.endswith('.txt'):
        match = re.search(r'bs_(\d+)_ngl_(\d+)', file)
        if match:
            bs, ngl = match.groups()
            with open(os.path.join(results_dir, file)) as f:
                content = f.read()
                # 解析性能数据
                tokens_per_sec = re.search(r'(\d+\.\d+) tokens/s', content)
                if tokens_per_sec:
                    summary.append({
                        'batch_size': int(bs),
                        'n_gpu_layers': int(ngl),
                        'tokens_per_sec': float(tokens_per_sec.group(1))
                    })

# 排序并输出最佳配置
summary.sort(key=lambda x: x['tokens_per_sec'], reverse=True)
print("Top 5 configurations:")
for i, config in enumerate(summary[:5]):
    print(f"{i+1}. BS={config['batch_size']}, NGL={config['n_gpu_layers']}: {config['tokens_per_sec']:.2f} tokens/s")
EOF
```

### 配置优化脚本

```bash
#!/bin/bash
# optimize_config.sh - 自动配置优化

MODEL=${1:-"model.gguf"}
TEST_PROMPT="The quick brown fox jumps over the lazy dog."

echo "Starting configuration optimization..."

# 找到最佳批处理大小
echo "Optimizing batch size..."
BEST_BS=512
BEST_SPEED=0
for BS in 128 256 512 1024 2048; do
    SPEED=$(./llama-cli -m $MODEL -b $BS -p "$TEST_PROMPT" -n 1000 2>&1 | grep -oP '\d+\.\d+ tokens/s' | grep -oP '\d+\.\d+')
    if (( $(echo "$SPEED > $BEST_SPEED" | bc -l) )); then
        BEST_SPEED=$SPEED
        BEST_BS=$BS
    fi
done
echo "Best batch size: $BEST_BS ($BEST_SPEED tokens/s)"

# 找到最佳GPU层数
echo "Optimizing GPU layers..."
BEST_NGL=35
BEST_SPEED=0
for NGL in 20 25 30 35 40 45; do
    SPEED=$(./llama-cli -m $MODEL -ngl $NGL -p "$TEST_PROMPT" -n 1000 2>&1 | grep -oP '\d+\.\d+ tokens/s' | grep -oP '\d+\.\d+')
    if (( $(echo "$SPEED > $BEST_SPEED" | bc -l) )); then
        BEST_SPEED=$SPEED
        BEST_NGL=$NGL
    fi
done
echo "Best GPU layers: $BEST_NGL ($BEST_SPEED tokens/s)"

# 生成优化配置
echo "Optimized configuration:"
echo "./llama-cli -m $MODEL -b $BEST_BS -ngl $BEST_NGL --temp 0.8 --top-p 0.9"
```
