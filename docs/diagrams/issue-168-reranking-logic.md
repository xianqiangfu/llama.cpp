# 重排序业务逻辑图

```mermaid
flowchart TD
    A[开始重排序] --> B{是否存在多个候选项?}
    B -->|否| C[直接返回最优token]
    B -->|是| D[获取候选token列表]
    D --> E[加载重排序模型]
    E --> F[构建重排序输入]
    F --> G[编码查询文本]
    G --> H[编码候选项文档]
    H --> I[拼接查询和文档]
    I --> J[通过重排序模型打分]
    J --> K[计算相关性分数]
    K --> L{需要多轮重排序?}
    L -->|是| M[保留top-k候选项]
    M --> F
    L -->|否| N[按分数排序]
    N --> O[返回重排序后的结果]
    O --> P[结束]

    subgraph 重排序模型内部
        Q[输入层] --> R[编码器层]
        R --> S[多头注意力机制]
        S --> T[前馈神经网络]
        T --> U[输出层]
        U --> V[相关性分数]
    end

    J -.-> Q
```

## 核心组件

### 1. 重排序流程
- **候选收集**: 从解码器获取多个候选token
- **模型推理**: 使用重排序模型评估每个候选项
- **分数计算**: 计算查询与候选项的相关性
- **结果排序**: 按相关性分数重新排序

### 2. 重排序模型
- 基于 Transformer 架构
- 采用交叉注意力机制
- 输出相关性分数

### 3. 关键优势
- 提高解码质量
- 支持长文本重排序
- 可配置的重排序深度
