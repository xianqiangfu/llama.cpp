# 注意力机制实现分析

## 概述

llama.cpp 实现了多种注意力机制和位置编码方案，包括 RoPE（Rotary Positional Embedding）、M-RoPE（Multi-dimensional RoPE）、Vision RoPE、ALiBi（Attention with Linear Biases）等。本文档详细分析这些机制的核心原理和实现细节。

## RoPE（Rotary Positional Embedding）

### 1. 核心原理

RoPE 通过旋转操作将位置信息注入到查询（Query）和键（Key）向量中，同时保持相对位置编码的优势。

#### 1.1 数学原理

对于维度为 d 的向量，RoPE 将其分为 2D/2 对，每对进行旋转：

```
对于位置 pos，维度 i：
theta_i = pos * freq_base^(-2i/d)

对于向量对 (x_{2k}, x_{2k+1})：
x'_{2k}   = x_{2k}   * cos(theta_k) - x_{2k+1} * sin(theta_k)
x'_{2k+1} = x_{2k}   * sin(theta_k) + x_{2k+1} * cos(theta_k)
```

其中：
- `freq_base`：基础频率（通常为 10000）
- `pos`：位置索引
- `d`：总维度数
- `k`：维度对索引

#### 3.2 YaRN（Yet another RoPE extension）实现

YaRN 算法用于处理超出训练长度的上下文，通过平滑插值和缩放来保持性能。

**核心函数：**

```cpp
// YaRN ramp 函数
static float rope_yarn_ramp(const float low, const float high, const int i0) {
    const float y = (i0 / 2 - low) / MAX(0.001f, high - low);
    return 1 - MIN(1, MAX(0, y));
}

// YaRN 旋转计算
static void rope_yarn(
    float theta_extrap,      // 外推 theta
    float freq_scale,        // 频率缩放
    float corr_dims[2],      // 校正维度 [low, high]
    int64_t i0,              // 当前维度索引
    float ext_factor,        // 外推因子
    float mscale,            // 幅度缩放
    float * cos_theta,       // 输出：cos(theta)
    float * sin_theta)       // 输出：sin(theta)
{
    // 插值 theta
    float theta_interp = freq_scale * theta_extrap;
    float theta = theta_interp;
    
    if (ext_factor != 0.0f) {
        // 混合插值和外推
        float ramp_mix = rope_yarn_ramp(corr_dims[0], corr_dims[1], i0) * ext_factor;
        theta = theta_interp * (1 - ramp_mix) + theta_extrap * ramp_mix;
        
        // 幅度缩放校正
        mscale *= 1.0f + 0.1f * logf(1.0f / freq_scale);
    }
    
    *cos_theta = cosf(theta) * mscale;
    *sin_theta = sinf(theta) * mscale;
}
```

#### 4.1 线性缩放（Linear Scaling）

```
theta = theta / scale_factor
```

**特点：**
- 简单直接
- 在长上下文时性能下降明显
- 适用于小幅扩展

#### 4.2 YaRN 缩放

**核心思想：**
- 对低频维度使用插值
- 对高频维度使用外推
- 平滑过渡避免性能突降

**优势：**
- 更好的长上下文性能
- 保留局部和全局位置信息
- 被广泛采用（如 Mistral、Gemma）

#### 4.3 LongRoPE 缩放

**特点：**
- 针对超长上下文优化
- 使用两阶段缩放策略
- 保持训练时的频率分布

## M-RoPE（Multi-dimensional RoPE）

### 1. 概述

M-RoPE 扩展了标准 RoPE，支持多维度位置编码，主要用于多模态模型（如 Qwen-VL）。

### 2. 实现类型

#### 2.1 GGML_ROPE_TYPE_MROPE

```cpp
#define GGML_ROPE_TYPE_MROPE 8
```

**特点：**
- 支持 4 个维度：时间(t)、高度(h)、宽度(w)、额外(e)
- 使用 sections 参数指定每个维度的旋转维度数
- 自动应用 NEOX 排序

**示例：**
```
sections = [t=4, y=2, x=2, 0]
head_size = 18, n_dims = 16
旋转：[ttttyyxxttttyyxx00]
解释：
- t 部分：8 维（4 对）
- h 部分：4 维（2 对）
- w 部分：4 维（2 对）
- 未旋转：2 维
```

#### 2.2 GGML_ROPE_TYPE_IMROPE（Interleaved M-RoPE）

```cpp
#define GGML_ROPE_TYPE_IMROPE 40  // binary: 101000
```

**特点：**
- 交替使用多个维度的位置
- 仍然使用 NEOX 排序
- 适用于 Qwen3-VL

**示例：**
```
sections = [t=4, y=2, x=2, 0]
head_size = 18, n_dims = 16
旋转：[ttyxttyxttyxttyx00]
```

### 3. 实现细节

```cpp
GGML_API struct ggml_tensor * ggml_rope_multi(
    struct ggml_context * ctx,
    struct ggml_tensor  * a,   // 输入张量
    struct ggml_tensor  * b,   // 位置向量（4 * n_token）
    struct ggml_tensor  * c,   // 频率因子
    int                   n_dims,  // 旋转维度数
    int                   sections[GGML_MROPE_SECTIONS],  // 每个维度的维度数
    int                   mode,  // MROPE 或 IMROPE
    int                   n_ctx_orig,
    float                 freq_base,
    float                 freq_scale,
    float                 ext_factor,
    float                 attn_factor,
    float                 beta_fast,
    float                 beta_slow);
```

**M-RoPE 缓存初始化：**

```cpp
static void ggml_mrope_cache_init(
    float theta_base_t,  // 时间维度基础频率
    float theta_base_h,  // 高度维度基础频率
    float theta_base_w,  // 宽度维度基础频率
    float theta_base_e,  // 额外维度基础频率
    int sections[4],     // 每个维度的维度数
    bool is_imrope,      // 是否为 IMROPE
    bool indep_sects,    // 是否独立计算每个 section
    float freq_scale,
    const float * freq_factors,
    float corr_dims[2],
    int64_t ne0,
    float ext_factor,
    float mscale,
    float * cache,
    float sin_sign,
    float theta_scale)
{
    float theta_t = theta_base_t;
    float theta_h = theta_base_h;
    float theta_w = theta_base_w;
    float theta_e = theta_base_e;
    int sect_dims = sections[0] + sections[1] + sections[2] + sections[3];
    
    for (int64_t i0 = 0; i0 < ne0; i0 += 2) {
        int sector = (i0 / 2) % sect_dims;
        float theta = theta_t;
        
        if (is_imrope) {
            // 交错模式
            if (sector % 3 == 1 && sector < 3 * sections[1]) {
                theta = theta_h;
            } else if (sector % 3 == 2 && sector < 3 * sections[2]) {
                theta = theta_w;
            } else if (sector % 3 == 0 && sector < 3 * sections[0]) {
                theta = theta_t;
            } else {
                theta = theta_e;
            }
        } else {
            // 标准 M-RoPE
            if (sector >= sections[0] && sector < sec_w) {
                theta = theta_h;
            } else if (sector >= sec_w && sector < sec_w + sections[2]) {
                theta = theta_w;
            } else if (sector >= sec_w + sections[2]) {
                theta = theta_e;
            }
        }
        
        // 应用 YaRN 缩放
        rope_yarn(theta, ...);
    }
}
```

## Vision RoPE

### 1. 概述

Vision RoPE 专为视觉模型设计，支持 2D 空间位置编码（高度和宽度）。

### 2. 实现类型

```cpp
#define GGML_ROPE_TYPE_VISION 24
```

**特点：**
- 2 个维度：高度(y)、宽度(x)
- 使用 sections 参数指定每个维度的旋转维度数
- 自动应用 NEOX 排序
- 每个维度独立计算 theta

**示例：**
```
sections = [y=4, x=4, 0, 0]
head_size = 8, n_dims = 4
旋转：[yyyyxxxx]
解释：
- y 部分：4 维（y 方向）
- x 部分：4 维（x 方向）
```

**与 M-RoPE 的区别：**

| 特性 | M-RoPE | Vision RoPE |
|------|--------|-------------|
| 维度数 | 4 (t,h,w,e) | 2 (y,x) |
| theta 计算 | 共享索引 | 每个维度独立索引 |
| 应用场景 | Qwen-VL 等 | 视觉编码器 |

## ALiBi（Attention with Linear Biases）

### 1. 核心原理

ALiBi 不将位置信息注入到 Q/K 向量中，而是在注意力分数上添加线性位置偏置。

```
attn_score = Q @ K^T + m * |i - j|
```

其中：
- `m`：可学习的斜率参数（每个 head 一个）
- `i, j`：查询和键的位置
- `|i - j|`：绝对位置差

### 2. 实现配置

```cpp
struct llama_hparams {
    bool use_alibi = false;          // 是否启用 ALiBi
    float f_max_alibi_bias = 0.0f;   // 最大 ALiBi 偏置
};
```

**参数说明：**
- `use_alibi`：启用 ALiBi 位置编码
- `f_max_alibi_bias`：限制偏置的最大值，防止数值不稳定

### 3. 优势与限制

**优势：**
- 自然支持外推到更长上下文
- 不需要重新训练即可扩展上下文
- 计算开销小

**限制：**
- 长距离依赖性能可能下降
- 偏置需要精心设计

## 注意力机制优化

### 1. Flash Attention

**概述：**
Flash Attention 是一种高效的注意力计算算法，通过分块计算和重计算来减少内存访问。

**实现：**

```cpp
enum clip_flash_attn_type {
    CLIP_FLASH_ATTN_TYPE_AUTO     = -1,  // 自动选择
    CLIP_FLASH_ATTN_TYPE_DISABLED = 0,   // 禁用
    CLIP_FLASH_ATTN_TYPE_ENABLED  = 1,   // 启用
};
```

**优势：**
- 减少 GPU 内存访问（HBM -> SRAM）
- 支持更长的序列长度
- 提高计算吞吐量

### 2. KV Cache 优化

**概述：**
KV Cache 缓存之前的键值对，避免重复计算。

**实现细节：**
- 支持 PagedAttention（vLLM 风格）
- 支持稀疏注意力（Sparse Attention）
- 支持滑动窗口注意力（Sliding Window）

### 3. 注意力剪枝

**概述：**
通过限制注意力权重来提高效率。

**实现配置：**

```cpp
struct llama_hparams {
    bool attn_soft_cap = false;  // 启用注意力软限制
    float f_clamp_kqv = 0.0f;    // 限制 KQV 的值
};
```

## 不同位置编码的优缺点对比

### 1. RoPE

**优点：**
- 保持相对位置信息
- 理论上支持无限长序列（配合缩放）
- 广泛采用，生态成熟

**缺点：**
- 长上下文时需要缩放策略
- 外推性能依赖缩放方法
- 计算复杂度略高

**适用场景：**
- 通用大语言模型
- 需要长上下文的任务
- 相对位置重要的任务

### 2. M-RoPE

**优点：**
- 支持多维度位置编码
- 适合多模态任务
- 保留空间结构信息

**缺点：**
- 实现复杂度高
- 计算开销大
- 参数调优困难

**适用场景：**
- 视觉-语言模型（Qwen-VL）
- 视频理解
- 3D 数据处理

### 3. ALiBi

**优点：**
- 天然支持外推
- 实现简单
- 计算效率高

**缺点：**
- 长距离依赖性能下降
- 不保留位置信息
- 调优空间有限

**适用场景：**
- 需要长上下文但不要求精确位置
- 推理资源受限的场景
- 训练后需要扩展上下文

### 4. Vision RoPE

**优点：**
- 专门针对视觉任务优化
- 保留 2D 空间结构
- 与图像补丁对齐

**缺点：**
- 仅适用于视觉任务
- 需要额外维度信息
- 通用性差

**适用场景：**
- 图像理解模型
- 视觉 Transformer
- 多模态编码器

## 性能优化建议

### 1. 选择合适的位置编码

| 需求 | 推荐 | 理由 |
|------|------|------|
| 通用 LLM | RoPE + YaRN | 平衡性能和易用性 |
| 超长上下文 | RoPE + LongRoPE | 专门优化 |
| 多模态 | M-RoPE | 支持多维度 |
| 视觉任务 | Vision RoPE | 保留空间信息 |
| 外推需求 | ALiBi | 天然支持 |

### 2. 调优参数

**RoPE 参数：**
- `freq_base`：通常 10000，可根据任务调整
- `freq_scale`：控制位置信息强度
- `n_ctx_orig`：原始训练长度，影响缩放

**YaRN 参数：**
- `beta_fast`：控制高频维度的插值速度
- `beta_slow`：控制低频维度的插值速度
- `ext_factor`：控制外推强度

### 3. 注意力优化

- **启用 Flash Attention**：显著提升速度
- **使用 KV Cache**：减少重复计算
- **批处理**：提高 GPU 利用率
- **混合精度**：使用 FP16/BF16

## 测试与验证

### 2. 性能基准

- **标准 RoPE**：基准性能
- **M-RoPE**：通常慢 20-30%
- **Vision RoPE**：与标准 RoPE 相当
- **ALiBi**：略快（避免旋转计算）

## 总结

llama.cpp 实现了丰富多样的注意力机制和位置编码方案：

1. **RoPE 系列**：标准、NeoX、M-RoPE、Vision RoPE
2. **缩放方案**：线性、YaRN、LongRoPE
3. **替代方案**：ALiBi
4. **优化技术**：Flash Attention、KV Cache

这些实现为不同类型的模型和任务提供了灵活的选择，同时通过 GGML 的高效计算保证了性能。开发者可以根据具体需求选择最合适的注意力机制配置。
