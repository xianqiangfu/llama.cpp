# 多模态输入处理机制分析

## 概述

llama.cpp 通过 `libmtmd` 库提供多模态输入支持，主要包括图像和音频输入处理。本文档详细分析多模态输入的预处理流程、模型加载方式和推理实现细节。

## 核心架构

### 1. 主要组件

#### 1.1 mtmd_context（多模态上下文）

```cpp
struct mtmd_context {
    struct clip_ctx * ctx_v;  // 视觉编码器上下文
    struct clip_ctx * ctx_a;  // 音频编码器上下文
    std::vector<float> image_embd_v;  // 图像嵌入向量

    bool print_timings;
    int n_threads;
    std::string media_marker;  // 媒体标记符，默认为 "<__media__>"
    const int n_embd_text;  // 文本模型的嵌入维度
    const llama_vocab * vocab;  // 文本模型的词表

    // 特殊标记
    std::string img_beg;  // 图像开始标记
    std::string img_end;  // 图像结束标记
    std::string aud_beg;  // 音频开始标记
    std::string aud_end;  // 音频结束标记

    // 切片模板（用于高分辨率图像处理）
    mtmd_slice_tmpl slice_tmpl;
    std::vector<llama_token> tok_ov_img_start;   // 总览图像开始标记
    std::vector<llama_token> tok_ov_img_end;     // 总览图像结束标记
    std::vector<llama_token> tok_slices_start;   // 所有切片开始标记
    std::vector<llama_token> tok_slices_end;     // 所有切片结束标记
    std::vector<llama_token> tok_sli_img_start;  // 单个切片开始标记
    std::vector<llama_token> tok_sli_img_end;    // 单个切片结束标记
    std::vector<llama_token> tok_sli_img_mid;    // 切片间标记

    std::unique_ptr<mtmd_audio_preprocessor> audio_preproc;
    std::unique_ptr<mtmd_image_preprocessor> image_preproc;
};
```

#### 1.2 clip_ctx（CLIP编码器上下文）

```cpp
struct clip_ctx {
    clip_model model;  // CLIP 模型

    gguf_context_ptr ctx_gguf;
    ggml_context_ptr ctx_data;

    std::vector<ggml_backend_t> backend_ptrs;
    std::vector<ggml_backend_buffer_type_t> backend_buft;

    ggml_backend_t backend;  // 后端（CPU 或 GPU）
    ggml_backend_t backend_cpu;
    ggml_backend_buffer_ptr buf;

    int max_nodes;
    ggml_backend_sched_ptr sched;
    clip_flash_attn_type flash_attn_type;
    bool is_allocated;

    bool no_alloc;
    std::map<ggml_backend_dev_t, size_t> mem_usage;
};
```

### 2. 数据结构

#### 2.1 mtmd_bitmap（位图数据）

```cpp
struct mtmd_bitmap {
    uint32_t nx;  // 宽度
    uint32_t ny;  // 高度
    std::vector<unsigned char> data;  // RGBRGBRGB... 格式的数据
    std::string id;  // 可选的用户定义 ID，用于 KV 缓存跟踪
    bool is_audio;  // true 表示音频数据
};
```

#### 2.2 mtmd_image_tokens（图像token）

```cpp
struct mtmd_image_tokens {
    uint32_t nx;  // x 方向的 token 数量
    uint32_t ny;  // y 方向的 token 数量
    mtmd_pos_type pos;  // 位置编码类型
    uint32_t image_idx;  // 图像索引（用于 HunyuanVL）
    clip_image_f32_batch batch_f32;  // 预处理后的图像补丁
    std::string id;  // 可选 ID

    uint32_t n_tokens() const {
        if (pos == MTMD_POS_TYPE_HUNYUANVL) {
            // [BOI] [row0 tokens + newline] ... [row(ny-1) tokens + newline] [EOI]
            return (nx + 1) * ny + 2;
        }
        return nx * ny;
    }
};
```

#### 2.3 位置编码类型

```cpp
enum mtmd_pos_type {
    MTMD_POS_TYPE_NORMAL,    // 标准位置编码，位置数等于 token 数
    MTMD_POS_TYPE_MROPE,     // Qwen-VL M-RoPE 风格，每张图像占用 max(t,h,w) 位置
    MTMD_POS_TYPE_HUNYUANVL, // HunyuanVL M-RoPE + BOI/EOI/newline 布局
};
```

## 多模态输入预处理流程

### 1. 图像预处理流程

#### 1.1 初始化阶段

```
1. 创建 mtmd_context
   ├─ 检查 media_marker（默认 "<__media__>"）
   ├─ 获取文本模型的嵌入维度和词表
   ├─ 根据解码器的 RoPE 类型设置位置编码类型
   └─ 初始化图像预处理器

2. 加载 CLIP 模型（mmproj 文件）
   ├─ 使用 clip_init() 加载 GGUF 格式的多模态投影器
   ├─ 初始化后端（CPU 或 GPU）
   ├─ 分配计算图和调度器
   └─ 可选：执行预热编码
```

#### 1.2 图像处理阶段

```
1. 图像解码（由调用方完成）
   ├─ 支持 RGB 格式（RGBRGBRGB... 布局）
   ├─ 数据长度必须为 nx * ny * 3 字节
   └─ 可选：设置 image ID 用于 KV 缓存跟踪

2. 图像预处理（在 mtmd_tokenize 中）
   ├─ 检测输入中的 media_marker
   ├─ 为每个标记创建 mtmd_bitmap
   └─ 调用图像预处理器进行预处理

3. 图像编码（在 mtmd_encode_chunk 中）
   ├─ 将图像转换为 CLIP 输入格式
   ├─ 提取图像特征
   ├─ 应用多模态投影器
   └─ 生成图像嵌入向量
```

### 2. 音频预处理流程

#### 2.1 音频数据格式

```cpp
// 音频位图数据
mtmd_bitmap * mtmd_bitmap_init_from_audio(
    size_t n_samples,
    const float * data
);

// 特点：
// - 数据格式：PCM F32（浮点型）
// - 数据长度：n_samples * sizeof(float) 字节
// - 采样率：通常为 16000 Hz（Whisper）
```

#### 2.2 音频处理流程

```
1. 音频解码（由调用方完成）
   ├─ 支持多种音频格式（WAV、MP3 等）
   ├─ 转换为 PCM F32 格式
   └─ 可选：重采样到目标采样率

2. 音频预处理
   ├─ 提取 Mel 频谱图
   ├─ 应用音频预处理器
   └─ 生成音频特征

3. 音频编码
   ├─ 将 Mel 频谱图转换为音频 token
   ├─ 应用多模态投影器
   └─ 生成音频嵌入向量
```

### 3. 文本与多模态融合

#### 3.1 分词流程

```cpp
int32_t mtmd_tokenize(
    mtmd_context * ctx,
    mtmd_input_chunks * output,
    const mtmd_input_text * text,
    const mtmd_bitmap ** bitmaps,
    size_t n_bitmaps
);
```

**流程：**

```
1. 解析输入文本中的 media_marker
   ├─ 使用 text->media_marker 作为分隔符
   ├─ 统计标记数量，必须与 bitmaps 数量匹配
   └─ 返回错误码：
      ├─ 0：成功
      ├─ 1：位图数量与标记数量不匹配
      └─ 2：图像预处理错误

2. 创建 input_chunks
   ├─ 分割文本为多个 chunk
   ├─ 每个 chunk 可以是：
   │  ├─ MTMD_INPUT_CHUNK_TYPE_TEXT（文本）
   │  ├─ MTMD_INPUT_CHUNK_TYPE_IMAGE（图像）
   │  └─ MTMD_INPUT_CHUNK_TYPE_AUDIO（音频）
   └─ 插入特殊标记（BOI、EOI 等）

3. 处理每个 chunk
   ├─ 文本 chunk：调用文本模型分词器
   ├─ 图像 chunk：调用图像预处理器
   └─ 音频 chunk：调用音频预处理器

4. 返回分词结果
   ├─ mtmd_input_chunks 包含所有 chunk
   └─ 每个 chunk 包含对应的 token
```

#### 3.2 编码流程

```cpp
int32_t mtmd_encode_chunk(
    mtmd_context * ctx,
    const mtmd_input_chunk * chunk
);
```

**流程：**

```
1. 检查 chunk 类型
   ├─ 文本：跳过编码（由文本模型处理）
   ├─ 图像：调用 clip_image_encode()
   └─ 音频：调用音频编码器

2. 图像编码
   ├─ 调用 CLIP 模型的前向传播
   ├─ 应用多模态投影器
   ├─ 将图像特征投影到文本嵌入空间
   └─ 存储结果到 ctx->image_embd_v

3. 音频编码
   ├─ 调用音频模型的前向传播
   ├─ 应用多模态投影器
   └─ 存储结果到音频嵌入空间
```

## 多模态模型加载方式

### 1. 模型文件结构

```
llama.cpp 多模态模型由两部分组成：

1. 主模型（LLM）文件
   ├─ 文件格式：GGUF
   ├─ 包含：语言模型权重
   ├─ 文件名示例：gemma-3-4b-it-Q4_K_M.gguf
   └─ 通过 -m 选项指定

2. 多模态投影器文件（mmproj）
   ├─ 文件格式：GGUF
   ├─ 包含：
   │  ├─ CLIP 模型权重（视觉编码器）
   │  ├─ 音频编码器权重（如果支持）
   │  └─ 多模态投影器权重
   ├─ 文件名示例：mmproj-gemma-3-4b-it-Q4_K_M.gguf
   └─ 通过 --mmproj 选项指定
```

### 2. 加载方式

#### 2.1 方式 1：使用 -hf 选项（推荐）

```bash
# 从 Hugging Face 自动下载
llama-mtmd-cli -hf ggml-org/gemma-3-4b-it-GGUF

# 禁用多模态功能
llama-server -hf ggml-org/gemma-3-4b-it-GGUF --no-mmproj

# 使用本地 mmproj 文件
llama-server -hf ggml-org/gemma-3-4b-it-GGUF --mmproj local_file.gguf
```

**特点：**
- 自动下载匹配的模型和投影器
- 简化使用流程
- 支持禁用多模态功能

#### 2.2 方式 2：分别指定模型文件

```bash
# 使用本地文件
llama-mtmd-cli -m gemma-3-4b-it-Q4_K_M.gguf \
                --mmproj mmproj-gemma-3-4b-it-Q4_K_M.gguf

llama-server -m gemma-3-4b-it-Q4_K_M.gguf \
             --mmproj mmproj-gemma-3-4b-it-Q4_K_M.gguf
```

**特点：**
- 完全控制模型文件
- 支持自定义组合
- 适合离线使用

### 3. 模型初始化流程

```cpp
mtmd_context * mtmd_init_from_file(
    const char * mmproj_fname,
    const llama_model * text_model,
    const mtmd_context_params ctx_params
);
```

**流程：**

```
1. 加载 mmproj 文件
   ├─ 使用 GGUF 库读取文件
   ├─ 解析元数据（模型类型、参数等）
   └─ 验证模型兼容性

2. 初始化 CLIP 上下文
   ├─ 创建 clip_ctx 结构
   ├─ 选择后端（CPU 或 GPU）
   ├─ 初始化调度器
   └─ 分配内存缓冲区

3. 配置多模态参数
   ├─ 设置媒体标记符
   ├─ 配置 Flash Attention 类型
   ├─ 设置线程数
   └─ 配置图像 token 范围

4. 初始化预处理器
   ├─ 根据模型类型选择预处理器
   ├─ 配置图像预处理参数
   └─ 配置音频预处理参数

5. 可选：执行预热编码
   ├─ 编码一个示例图像/音频
   ├─ 预热 GPU 缓存
   └─ 减少首次推理延迟

6. 返回 mtmd_context
   └─ 包含所有初始化状态
```

### 4. GPU 卸载配置

```cpp
struct mtmd_context_params {
    bool use_gpu;  // 是否使用 GPU（默认 true）

    // 禁用 GPU 卸载
    // llama-server -hf ... --no-mmproj-offload
};
```

**实现：**

```
1. 后端初始化
   ├─ 读取 MTMD_BACKEND_DEVICE 环境变量
   ├─ 尝试初始化指定后端
   ├─ 回退到默认 GPU 后端
   └─ 最终回退到 CPU 后端

2. 内存分配
   ├─ GPU 后端：使用设备内存
   ├─ CPU 后端：使用主机内存
   └─ 混合模式：部分卸载到 GPU

3. 性能考虑
   ├─ GPU 卸载：显著提高推理速度
   ├─ GPU 限制：显存占用较高
   └─ CPU 回退：兼容性最好但速度慢
```

## 多模态推理实现细节

### 1. 输入 token 生成

#### 1.1 分词结果结构

```cpp
struct mtmd_input_chunk {
    mtmd_input_chunk_type type;
    std::vector<llama_token> tokens_text;    // 文本 token
    mtmd_image_tokens_ptr tokens_image;     // 图像 token
    mtmd_audio_tokens_ptr tokens_audio;     // 音频 token
};
```

#### 1.2 token 序列构建

```
示例输入："这是一张图片：<__media__> 请描述它。"

分词结果：
Chunk 0: [文本] "这是一张图片："
  ├─ tokens: [token_1, token_2, ..., token_n]
  └─ type: MTMD_INPUT_CHUNK_TYPE_TEXT

Chunk 1: [图像] <__media__>
  ├─ tokens_image:
  │  ├─ nx: 24 (x 方向 token 数)
  │  ├─ ny: 24 (y 方向 token 数)
  │  └─ n_tokens: 576 (24*24)
  └─ type: MTMD_INPUT_CHUNK_TYPE_IMAGE

Chunk 2: [文本] " 请描述它。"
  ├─ tokens: [token_m, token_m+1, ..., token_p]
  └─ type: MTMD_INPUT_CHUNK_TYPE_TEXT
```

### 2. 嵌入向量获取

```cpp
float * mtmd_get_output_embd(mtmd_context * ctx);
```

**返回值：**
- 指向嵌入向量缓冲区的指针
- 缓冲区大小：`llama_model_n_embd_inp(model) * n_tokens * sizeof(float)`

### 3. 解码器集成

#### 3.1 位置编码处理

```cpp
bool mtmd_decode_use_mrope(const mtmd_context * ctx);
bool mtmd_decode_use_non_causal(const mtmd_context * ctx);
```

**M-RoPE 模型：**
- Qwen-VL、Qwen2.5-VL 等模型使用
- 每个图像占用 `max(t, h, w)` 位置
- 支持多维度位置编码

**标准模型：**
- 位置数等于 token 数
- 使用标准 1D 位置编码

#### 3.2 KV 缓存管理

```cpp
const char * mtmd_bitmap_get_id(const mtmd_bitmap * bitmap);
void mtmd_bitmap_set_id(mtmd_bitmap * bitmap, const char * id);
```

**用途：**
- 为每个图像/音频设置唯一 ID
- 用于 KV 缓存查找和复用
- 支持相同输入的缓存复用

### 4. 批处理支持

```cpp
bool clip_image_batch_encode(
    struct clip_ctx * ctx,
    int n_threads,
    const struct clip_image_f32_batch * imgs,
    float * vec
);
```

**优势：**
- 同时处理多张图像
- 提高 GPU 利用率
- 减少内存拷贝开销

### 5. 不同模型的特殊处理

#### 5.1 切片/平铺模型（LLaVA-UHD、MiniCPM-V、Llama 4）

```cpp
enum mtmd_slice_tmpl {
    MTMD_SLICE_TMPL_NONE,        // 无切片
    MTMD_SLICE_TMPL_MINICPMV_2_5,
    MTMD_SLICE_TMPL_MINICPMV_2_6,
    MTMD_SLICE_TMPL_LLAMA4,
    MTMD_SLICE_TMPL_IDEFICS3,
    MTMD_SLICE_TMPL_LFM2,
    MTMD_SLICE_TMPL_STEP3VL,
};
```

**处理流程：**

```
1. 图像分割
   ├─ 生成总览图像（低分辨率）
   ├─ 将高分辨率图像分割为多个切片
   └─ 每个切片独立编码

2. 特殊标记插入
   ├─ 总览图像：tok_ov_img_start + 嵌入 + tok_ov_img_end
   ├─ 切片集合：tok_slices_start + 所有切片 + tok_slices_end
   └─ 单个切片：tok_sli_img_start + 嵌入 + tok_sli_img_end

3. 行结束标记
   ├─ 每行切片后插入 tok_row_end
   ├─ 切片间插入 tok_sli_img_mid
   └─ 提供结构化空间信息
```

#### 5.2 HunyuanVL 特殊布局

```cpp
// HunyuanVL 布局示例
// [BOI] [row0 tokens + newline] ... [row(ny-1) tokens + newline] [EOI]
uint32_t n_tokens() const {
    if (pos == MTMD_POS_TYPE_HUNYUANVL) {
        return (nx + 1) * ny + 2;  // BOI + 每行+换行 + EOI
    }
    return nx * ny;
}
```

**特点：**
- 保留图像的行结构信息
- 每行末尾添加换行标记
- BOI/EOI 标记图像边界

#### 5.3 Qwen-VL M-RoPE

```cpp
mtmd_pos_type pos = MTMD_POS_TYPE_MROPE;

// 位置编码：max(t, h, w)
// t: 时间维度（通常为 1）
// h: 高度方向 token 数
// w: 宽度方向 token 数
llama_pos mtmd_input_chunk_get_n_pos(const mtmd_input_chunk * chunk);
```

**特点：**
- 多维度位置编码
- 支持时间、高度、宽度三个维度
- 适合视频和多帧图像

## 错误处理

### 1. 常见错误码

| 错误码 | 含义 | 解决方法 |
|--------|------|----------|
| 0 | 成功 | - |
| 1 | 位图与标记数量不匹配 | 检查输入和位图数组 |
| 2 | 图像预处理错误 | 检查图像格式和尺寸 |

### 2. 内存不足

**症状：**
- 模型加载失败
- 编码时崩溃

**解决方法：**
- 减小图像分辨率
- 禁用 GPU 卸载
- 使用更低的量化级别

### 3. 模型不兼容

**症状：**
- 维度不匹配错误
- 编码结果异常

**解决方法：**
- 验证主模型和 mmproj 文件匹配
- 检查模型版本兼容性
