# llama.cpp 项目概述

## 项目简介

llama.cpp 是一个用 C/C++ 编写的轻量级大语言模型推理框架，旨在在各种硬件平台上高效运行大语言模型（LLM）。该项目由 Georgi Gerganov 创建，于2023年3月首次发布，迅速成为开源LLM推理领域的重要项目之一。

### 项目特点

1. **轻量高效**: 代码简洁，资源占用低，适合在资源受限的设备上运行
2. **跨平台支持**: 支持 Windows、Linux、macOS 等主流操作系统
3. **多硬件后端**: 支持 CPU、GPU（CUDA、Metal、Vulkan、OpenCL 等）等多种硬件加速
4. **量化技术**: 提供多种量化方案，在保持模型精度的同时显著减少内存占用
5. **丰富的功能**: 支持批量推理、推测解码、多模态输入等高级功能
6. **活跃的社区**: 拥有庞大的开发者社区，持续更新和改进

### 项目目标

llama.cpp 的主要目标是：

- **降低使用门槛**: 让普通用户和开发者能够在标准硬件上运行大语言模型
- **提高推理效率**: 通过各种优化技术实现高效的模型推理
- **增强可移植性**: 支持多种平台和硬件环境，便于部署
- **促进开源发展**: 为开源LLM社区提供高质量的推理工具

## 核心特性

### 1. 多种硬件后端支持

llama.cpp 支持多种硬件加速后端，可以在不同平台上实现最佳性能：

- **CPU**: 基础 CPU 推理，支持 BLAS 加速（OpenBLAS、BLIS、Intel oneMKL）
- **CUDA**: NVIDIA GPU 支持，提供完整的 GPU 加速功能
- **Metal**: Apple Silicon 原生支持，利用 Metal 框架
- **Vulkan**: 跨平台 GPU 支持，支持多种 GPU 厂商
- **OpenCL**: 跨平台并行计算支持
- **SYCL**: Intel GPU 支持，使用 SYCL 框架
- **HIP**: AMD GPU 支持，通过 ROCm 生态
- **CANN**: 华为昇腾 NPU 支持
- **其他**: 还支持 MUSA、ZenDNN、OpenVINO、WebGPU 等多种后端

### 2. 先进的量化技术

量化是 llama.cpp 的核心特性之一，支持多种量化格式：

- **Q4_0/Q4_1**: 基础 4-bit 量化
- **Q5_0/Q5_1**: 5-bit 量化，平衡精度和性能
- **Q8_0**: 8-bit 量化，接近原始精度
- **Q2_K/Q3_K/Q4_K/Q5_K**: K-quant 量化系列，针对不同场景优化
- **IQ 系列**: 创新量化系列（IQ2_M、IQ2_XS、IQ3_XXS 等），提供极致压缩
- **混合精度**: 同一模型内使用不同量化策略

量化技术带来的优势：
- 显著减少内存占用（最高可达 70%+）
- 提高推理速度（减少内存访问和计算量）
- 扩大可运行的模型规模（在相同硬件上运行更大的模型）

### 3. 高级推理优化

#### 推测解码（Speculative Decoding）

使用草稿模型快速生成候选 token，然后由主模型验证，可以显著加速生成过程：

- **草稿模型**: 使用小模型生成草稿
- **n-gram 技术**: 基于 n-gram 统计的预测方法
- **混合模式**: 可以组合多种推测方法

#### Lookahead 优化

通过构建候选树并预测多个路径，减少实际的推理次数：

- 动态构建候选树
- 智能剪枝策略
- 高效验证机制

#### Flash Attention

优化的注意力机制实现，减少内存访问和计算开销：

- 支持多种 GPU 后端
- 自动检测和启用
- 显著提升长文本处理性能

### 4. KV Cache 优化

KV Cache（键值缓存）是提高推理性能的关键技术：

- **量化 KV Cache**: 支持 FP16、BF16、Q8_0、Q4_0 等多种格式
- **压缩存储**: 减少内存占用
- **自动管理**: 智能的缓存分配和释放

### 5. 多模态支持

通过 libmtmd 库支持图像和音频输入：

- **视觉模型**: Gemma 3、SmolVLM、Pixtral、Qwen2-VL、InternVL 等
- **音频模型**: Ultravox、Voxtral、Qwen3-ASR 等
- **混合模态**: Qwen2.5-Omni、Qwen3-Omni、Gemma 4 等

### 6. 批量推理

支持高效的批量处理：

- **连续批量**: 动态调整批处理大小
- **优先级调度**: 不同请求的优先级管理
- **资源隔离**: 不同请求的内存隔离

### 7. 多 GPU 支持

支持多 GPU 并行推理：

- **张量并行**: 将模型分布到多个 GPU
- **管道并行**: 流水线式处理
- **点对点访问**: GPU 间直接数据传输

### 8. 函数调用和工具使用

支持结构化输出和函数调用：

- **GBNF 语法**: 强大的语法约束系统
- **JSON 模式**: 确保 JSON 格式输出
- **工具调用**: 与外部工具和 API 集成

### 9. LoRA 适配器支持

支持 LoRA（Low-Rank Adaptation）微调模型：

- **动态加载**: 运行时加载 LoRA 适配器
- **多适配器**: 同时使用多个 LoRA
- **混合精度**: 不同精度级别的 LoRA

### 10. 丰富的工具和 API

提供多种使用方式：

- **命令行工具**: llama-cli、llama-server 等
- **C API**: 核心库接口
- **HTTP API**: OpenAI 兼容的 REST API
- **Python 绑定**: gguf-py 库
- **多种语言示例**: C++、C、Python、Swift、JavaScript 等

| 模型 | 量化 | CPU (8核) | GPU (RTX 3090) | Apple M2 |
|------|------|-----------|----------------|----------|
| LLaMA 7B | Q4_K_M | ~5 | ~60 | ~25 |
| LLaMA 13B | Q4_K_M | ~3 | ~45 | ~18 |
| LLaMA 33B | Q4_K_M | ~1.5 | ~30 | ~10 |
| Gemma 7B | Q4_K_M | ~6 | ~65 | ~28 |

| 模型 | 原始 (FP16) | Q8_0 | Q4_K_M | Q2_K |

| LLaMA 13B | ~26 GB | ~13 GB | ~8 GB | ~5 GB |
| LLaMA 33B | ~66 GB | ~33 GB | ~20 GB | ~13 GB |

- **推测解码**: 生成速度提升 2-3 倍
