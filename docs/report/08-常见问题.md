# 常见问题

## 概述

本章收集了 llama.cpp 使用过程中的常见问题和解决方案，帮助用户快速解决问题。

## 1. 安装和编译问题

### 1.1 编译错误

#### Q: 编译时出现 "ggml.h file not found"

**A:** 确保 CMake 配置正确，清理构建缓存：

```bash
rm -rf build
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release -j
```

#### Q: CUDA 编译失败

**A:** 检查 CUDA 安装和版本：

```bash
# 检查 CUDA 版本
nvcc --version

# 检查 CUDA 路径
echo $CUDA_HOME

# 重新配置
cmake -B build -DGGML_CUDA=ON -DCMAKE_CUDA_COMPILER=/usr/local/cuda/bin/nvcc
```

#### Q: Windows 上编译失败

**A:** 确保使用正确的生成器：

```cmd
# 使用 Visual Studio
cmake -B build -G "Visual Studio 17 2022" -DCMAKE_BUILD_TYPE=Release

# 使用 MinGW
cmake -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
```

### 1.2 依赖问题

#### Q: 找不到 OpenSSL 库

**A:** 安装 OpenSSL 开发包：

```bash
# Debian/Ubuntu
sudo apt-get install libssl-dev

# Fedora/RHEL
sudo dnf install openssl-devel

# Arch
sudo pacman -S openssl
```

#### Q: 找不到 BLAS 库

**A:** 安装 BLAS 库：

```bash
# OpenBLAS
sudo apt-get install libopenblas-dev

# Intel MKL
source /opt/intel/oneapi/setvars.sh
```

## 2. 模型加载问题

### 2.1 模型文件问题

#### Q: "failed to load model from file"

**A:** 检查模型文件：

```bash
# 1. 验证文件存在
ls -lh model.gguf

# 2. 检查文件完整性
md5sum model.gguf

# 3. 确认文件格式
file model.gguf
```

#### Q: 模型加载后崩溃

**A:** 检查内存和兼容性：

```bash
# 1. 检查可用内存
free -h

# 2. 尝试较小的上下文
./llama-cli -m model.gguf -c 1024

# 3. 禁用 GPU
./llama-cli -m model.gguf --n-gpu-layers 0
```

### 2.2 量化问题

#### Q: 量化后模型质量下降严重

**A:** 调整量化参数：

```bash
# 使用更高质量的量化
./llama-quantize model-f16.gguf model-q5_k.gguf Q5_K_M

# 使用重要性矩阵
./llama-quantize model-f16.gguf model-q4_k.gguf Q4_K_M \
  --imatrix imatrix.dat

# 对不同层使用不同量化
./llama-quantize model-f16.gguf model-mixed.gguf \
  --output-tensor-type q8_0 \
  --tensor-type-q4_k
```

#### Q: 量化速度很慢

**A:** 优化量化过程：

```bash
# 使用多线程
./llama-quantize model-f16.gguf model-q4_k.gguf Q4_K_M -t 8

# 使用 GPU 量化（如果支持）
./llama-quantize model-f16.gguf model-q4_k.gguf Q4_K_M --gpu
```

## 3. 推理性能问题

### 3.1 推理速度慢

#### Q: CPU 推理速度很慢

**A:** 优化 CPU 配置：

```bash
# 1. 使用多线程
./llama-cli -m model.gguf -t 8

# 2. 启用 BLAS 加速
cmake -B build -DGGML_BLAS=ON -DGGML_BLAS_VENDOR=OpenBLAS

# 3. 使用更激进的量化
./llama-cli -m model-Q2_K.gguf
```

#### Q: GPU 推理速度慢

**A:** 检查 GPU 配置：

```bash
# 1. 检查 GPU 利用率
nvidia-smi

# 2. 增加层数到 GPU
./llama-cli -m model.gguf -ngl 35

# 3. 检查 GPU 内存
nvidia-smi --query-gpu=memory.used,memory.total --format=csv

# 4. 使用 Flash Attention
./llama-cli -m model.gguf -ngl 35 --flash-attn
```

### 3.2 内存问题

#### Q: "CUDA out of memory"

**A:** 优化内存使用：

```bash
# 1. 减少层数到 GPU
./llama-cli -m model.gguf -ngl 20

# 2. 启用 KV Cache 量化
./llama-cli -m model.gguf --cache-type-k Q4_K --cache-type-v Q4_K

# 3. 减少上下文大小
./llama-cli -m model.gguf -c 1024

# 4. 启用统一内存
GGML_CUDA_ENABLE_UNIFIED_MEMORY=1 ./llama-cli -m model.gguf
```

#### Q: 内存泄漏

**A:** 检查和修复内存泄漏：

```bash
# 使用 Valgrind 检测
valgrind --leak-check=full ./llama-cli -m model.gguf

# 使用 AddressSanitizer
cmake -B build-asan -DLLAMA_SANITIZE_ADDRESS=ON
cmake --build build-asan
./build-asan/bin/llama-cli -m model.gguf
```

## 4. 输出质量问题

### 4.1 输出质量差

#### Q: 模型输出质量下降

**A:** 调整采样参数：

```bash
# 1. 调整温度
./llama-cli -m model.gguf --temp 0.7

# 2. 调整 Top-K
./llama-cli -m model.gguf --top-k 40

# 3. 调整 Top-P
./llama-cli -m model.gguf --top-p 0.9

# 4. 使用更高的量化
./llama-cli -m model-Q5_K_M.gguf
```

#### Q: 输出重复

**A:** 调整采样策略：

```bash
# 1. 增加温度
./llama-cli -m model.gguf --temp 1.0

# 2. 启用重复惩罚
./llama-cli -m model.gguf --repeat-penalty 1.1

# 3. 使用 Mirostat
./llama-cli -m model.gguf --mirostat 2 --mirostat-eta 0.1 --mirostat-tau 5.0
```

### 4.2 格式问题

#### Q: JSON 输出格式错误

**A:** 使用语法约束：

```bash
# 使用 GBNF 语法
./llama-cli -m model.gguf \
  -p "Generate a JSON object" \
  --grammar 'root ::= obj obj ::= "{" ws string ws ":" ws value ws "}" value ::= string | number | obj | arr'

# 使用 JSON Schema 转换
python json-schema-to-grammar.py schema.json > grammar.gbnf
./llama-cli -m model.gguf --grammar grammar.gbnf -p "Generate JSON"
```

#### Q: 代码输出错误

**A:** 使用语法约束和提示：

```bash
# 使用代码语法
./llama-cli -m model.gguf \
  -p "Write a Python function to sort a list" \
  --grammar 'root ::= "def sort_list(lst):" [^\n]*\n([^\n]*\n)*'

# 使用系统提示
./llama-cli -m model.gguf \
  -p "You are an expert Python programmer. Write clean, efficient code." \
  --prompt "Write a function to sort a list:"
```

## 5. 服务器问题

### 5.1 启动问题

#### Q: 服务器无法启动

**A:** 检查配置和依赖：

```bash
# 1. 检查端口占用
netstat -tlnp | grep 8080

# 2. 检查模型文件
ls -lh model.gguf

# 3. 检查日志
./llama-server -m model.gguf --log-debug

# 4. 尝试不同的端口
./llama-server -m model.gguf --port 8081
```

#### Q: 服务器启动后无法访问

**A:** 检查网络配置：

```bash
# 1. 检查防火墙
sudo ufw status
sudo ufw allow 8080/tcp

# 2. 检查绑定地址
./llama-server -m model.gguf --host 0.0.0.0

# 3. 检查网络连接
curl http://localhost:8080/health
```

### 5.2 性能问题

#### Q: 服务器响应慢

**A:** 优化服务器配置：

```bash
# 1. 增加批次大小
./llama-server -m model.gguf --batch-size 512

# 2. 增加并行数
./llama-server -m model.gguf -n-parallel 4

# 3. 启用连续批处理
./llama-server -m model.gguf --cont-batching

# 4. 增加 GPU 层数
./llama-server -m model.gguf -ngl 35
```

#### Q: 服务器崩溃

**A:** 检查稳定性和资源：

```bash
# 1. 检查内存使用
top -p $(pgrep llama-server)

# 2. 检查 GPU 使用
nvidia-smi

# 3. 查看崩溃日志
tail -f /var/log/llama-server.log

# 4. 使用守护进程
sudo systemctl start llama-server
```

## 6. 多模态问题

### 6.1 视觉模型问题

#### Q: 多模态模型无法加载

**A:** 检查模型和投影器：

```bash
# 1. 确认模型文件
ls -lh model.gguf mmproj.gguf

# 2. 使用正确的命令
./llama-mtmd-cli -m model.gguf --mmproj mmproj.gguf

# 3. 检查 HuggingFace 仓库
./llama-mtmd-cli -hf ggml-org/gemma-3-4b-it-GGUF
```

#### Q: 图像处理失败

**A:** 检查图像格式和依赖：

```bash
# 1. 检查图像格式
file image.jpg

# 2. 转换图像格式
convert image.png image.jpg

# 3. 检查图像大小
identify image.jpg

# 4. 使用正确的命令
./llama-mtmd-cli -m model.gguf --mmproj mmproj.gguf --image image.jpg
```

### 6.2 音频模型问题

#### Q: 音频转录不准确

**A:** 调整音频质量和参数：

```bash
# 1. 检查音频质量
ffmpeg -i audio.wav

# 2. 转换音频格式
ffmpeg -i input.mp3 -ar 16000 -ac 1 output.wav

# 3. 调整采样参数
./llama-mtmd-cli -m model.gguf --audio audio.wav --temp 0.3
```

## 7. 高级功能问题

### 7.1 推测解码问题

#### Q: 推测解码无效

**A:** 检查配置和统计：

```bash
# 1. 检查草稿模型
ls -lh draft-model.gguf

# 2. 检查接受率
./llama-cli -m model.gguf --draft-model draft.gguf \
  --draft-n-max 5 --stats

# 3. 调整参数
./llama-cli -m model.gguf --draft-model draft.gguf \
  --draft-n-max 3 --draft-p-min 0.05
```

#### Q: n-gram 推测效果差

**A:** 调整 n-gram 参数：

```bash
# 1. 调整 n-gram 大小
./llama-cli -m model.gguf --spec-type ngram-mod \
  --spec-ngram-mod-n-match 24 --spec-ngram-mod-n-max 64

# 2. 尝试不同的方法
./llama-cli -m model.gguf --spec-type ngram-map-k \
  --spec-ngram-map-k-size-n 12 --spec-ngram-map-k-size-m 48
```

### 7.2 LoRA 问题

#### Q: LoRA 适配器无法加载

**A:** 检查 LoRA 文件和配置：

```bash
# 1. 确认 LoRA 文件
ls -lh lora-adapter.gguf

# 2. 检查兼容性
./llama-cli -m base-model.gguf --lora lora-adapter.gguf --verbose

# 3. 调整缩放
./llama-cli -m base-model.gguf --lora lora-adapter.gguf --lora-scale 0.5
```

#### Q: 多个 LoRA 冲突

**A:** 调整 LoRA 配置：

```bash
# 1. 调整缩放比例
./llama-cli -m base-model.gguf \
  --lora lora1.gguf \
  --lora lora2.gguf \
  --lora-scales 0.3,0.7

# 2. 分离使用
./llama-cli -m base-model.gguf --lora lora1.gguf
./llama-cli -m base-model.gguf --lora lora2.gguf
```

## 8. 平台特定问题

### 8.1 Windows 问题

#### Q: Windows 上路径问题

**A:** 使用正确的路径格式：

```cmd
# 使用正斜杠
llama-cli -m C:/models/model.gguf

# 或使用引号
llama-cli -m "C:\models\model.gguf"

# 或使用相对路径
cd C:\models
llama-cli -m model.gguf
```

#### Q: Windows 上 GPU 问题

**A:** 检查 GPU 驱动和 CUDA：

```cmd
# 检查 CUDA 安装
nvcc --version

# 检查 GPU 驱动
nvidia-smi

# 重新配置 CMake
cmake -B build -DGGML_CUDA=ON -DCMAKE_CUDA_COMPILER=C:/Program\ Files/NVIDIA\ GPU\ Computing\ Toolkit/CUDA/v12.0/bin/nvcc.exe
```

### 8.2 macOS 问题

#### Q: macOS 上 Metal 不工作

**A:** 检查 Metal 支持：

```bash
# 检查 Metal 支持
system_profiler SPDisplaysDataType | grep Metal

# 重新编译
cmake -B build -DGGML_METAL=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release -j

# 禁用 Metal
./llama-cli -m model.gguf --n-gpu-layers 0
```

#### Q: macOS 上性能问题

**A:** 优化 macOS 配置：

```bash
# 1. 增加 GPU 层数
./llama-cli -m model.gguf -ngl 35

# 2. 使用 Metal Performance Shaders
./llama-cli -m model.gguf --metal

# 3. 检查内存使用
top -pid $(pgrep llama-cli)
```

### 8.3 Linux 问题

#### Q: Linux 上权限问题

**A:** 修复权限：

```bash
# 1. 修复文件权限
chmod +x llama-cli

# 2. 修复模型文件权限
chmod 644 model.gguf

# 3. 使用正确的用户
sudo -u llama ./llama-cli -m model.gguf
```

#### Q: Linux 上库文件问题

**A:** 设置库路径：

```bash
# 1. 检查库路径
ldd ./llama-cli

# 2. 设置 LD_LIBRARY_PATH
export LD_LIBRARY_PATH=/usr/local/cuda/lib64:$LD_LIBRARY_PATH

# 3. 使用 rpath
cmake -B build -DCMAKE_INSTALL_RPATH=/usr/local/cuda/lib64
```

## 11. 总结

llama.cpp 的常见问题主要集中在：

1. **安装编译**: 依赖、配置、平台兼容性
2. **模型加载**: 文件格式、内存需求
3. **推理性能**: GPU/CPU 配置、内存管理
4. **输出质量**: 采样参数、量化级别
5. **服务器部署**: 启动、网络、性能
6. **多模态功能**: 模型加载、图像处理
7. **高级功能**: 推测解码、LoRA
8. **平台特定**: Windows、macOS、Linux

通过理解这些常见问题和解决方案，用户可以更有效地使用 llama.cpp 进行 LLM 推理。
